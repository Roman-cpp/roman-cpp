## Проекты на Go

### Nexus — платформа личных утилит из 5 Go-сервисов
`github.com/Roman-cpp/Nexus` · Go, PostgreSQL, nginx, Docker Compose, MinIO, LiveKit, Prometheus/Grafana/Loki

Собственный проект: пять независимых Go-сервисов (auth, nexus, wiki, chat, voice-rooms) за единым nginx-gateway, развёрнуто на своём сервере под TLS.

- **Спроектировал схему доверия между сервисами.** Наружу открыт только gateway; сами сервисы живут в docker-сети без публикации портов. nginx через `auth_request` ходит в auth-service и проставляет вниз `X-User-Id` — сервисы не проверяют JWT сами и не знают про пароли. Публичные маршруты (шаринг файла и заметки по токену) объявлены выше общего auth-блока, и gateway на них принудительно затирает заголовки личности, чтобы клиент не подставил свои.
- **Вынес миграции в отдельные сервисы compose.** Каждый `*-migrate` — самостоятельный бинарник с `go:embed`-миграциями; сервисы стартуют по `service_completed_successfully`. Это даёт накатить или откатить схему перед деплоем, не перезапуская приложение.
- **Закрыл наблюдаемость целиком:** JSON access-логи gateway со сквозным `X-Request-ID` → Promtail → Loki, метрики сервисов → Prometheus, дашборды провижинятся из репозитория. Один запрос прослеживается от nginx до SQL.
- **Прод отделён от dev на уровне стека:** dev — hot-reload через `air` и Vite; прод — статические бинарники из multi-stage сборок, TLS с автопродлением certbot, БД и Grafana доступны только через SSH-туннель.

*Компромиссы, на которые пошёл осознанно:* изоляция сервисов сделана на уровне отдельных БД в одном инстансе Postgres, а не отдельных кластеров и пользователей; межсервисного взаимодействия по gRPC нет — сервисы общаются только через gateway. Для текущего масштаба это дешевле, а точки роста описаны в `docs/`.

### wiki-service — вики с деревом страниц, ревизиями и полнотекстом
`services/wiki-service` в Nexus · Go, chi, pgx, PostgreSQL

Самый содержательный сервис платформы: пространства, дерево страниц до 6 уровней, правка с историей, поиск.

- **Решил задачу конкурентной правки.** `PATCH` требует `If-Match` с ETag, собранным из id и счётчика `version`. Проверка сделана дважды намеренно: в сервисе — чтобы вернуть 409 с актуальным ETag, не трогая базу, и в самом `UPDATE ... WHERE id = $1 AND version = $7` — потому что между чтением и записью страницу мог сохранить кто-то ещё, и проверка в сервисе сама по себе ничего не гарантирует. Строка берётся `FOR UPDATE`, так как правка тут же пишет производные от прочитанного.
- **Денормализовал дерево под три разных запроса:** `parent_id + position` держат структуру, `path` даёт человекочитаемый адрес и поиск одним индексом, `depth` проверяет предел вложенности без рекурсии на каждой вставке. Порядок чтения (оглавление, «назад/вперёд», нумерация) — один рекурсивный CTE, накапливающий `sort_path`. Сквозную нумерацию разделов не храню: вставка одного раздела переписывала бы половину таблицы.
- **Перенос поддерева — один запрос с data-modifying CTE:** читает старые пути, пишет их в `page_redirects` и проставляет новые пути с глубинами. Подзапросы в `WITH` видят снимок таблицы до `UPDATE`, поэтому редиректы сохраняют именно старые значения. Перед переносом проверяются два инварианта: страница не переезжает внутрь своего поддерева и высота поддерева не выбивает лимит глубины.
- **Два режима поиска с разной механикой:** `ILIKE` по заголовкам для боковой панели (незаконченное слово — норма при поиске по мере ввода, полнотекст его не найдёт) и `tsvector` с весами A/B, `websearch_to_tsquery` и `ts_headline` для полнотекста. `search_vector` — generated column, поэтому индекс не может разойтись с контентом. Курсор у режимов разный: keyset для заголовков, смещение для релевантности — для клиента непрозрачен в обоих случаях.
- **Проверка прав — единственной точкой входа** (`SpaceService.Require`): остальные сервисы получают `space_id` только через неё, поэтому проверку нельзя забыть. Роль ниже `viewer` даёт 404, а не 403 — существование чужого пространства не раскрывается.

### auth-service — регистрация, вход, второй фактор
`github.com/Roman-cpp/auth-service` · Go, PostgreSQL, JWT, SMTP · 38 тестов

- Подтверждение почты и второй фактор — одноразовые коды с TTL, кулдауном на переотправку и лимитом неверных попыток; конфиг валидируется на старте (короткий `JWT_SECRET`, кулдаун длиннее TTL и MFA-токен короче срока жизни кода не дадут сервису подняться).
- **Типы токенов разделены и не взаимозаменяемы:** тест `TestMFATokenIsRejectedAsAccessToken` и парный к нему фиксируют, что промежуточный токен второго шага нельзя предъявить как access и наоборот; отдельный тест — на невозможность переиспользовать MFA-токен повторно.
- Ответы на неизвестный email неотличимы от ответов на существующий — перебор аккаунтов через регистрацию и восстановление не работает. Тесты написаны на фейковых репозиториях, без мок-фреймворков: проверяется поведение сценария, а не порядок вызовов.

## Open source

### Docpoint — десктопное приложение для документирования и отладки API
`github.com/Roman-cpp/Docpoint` · Rust, Tauri 2, SQLite/sqlx, reqwest, WebAssembly, React 19, TypeScript
AGPL-3.0 · релиз v1.2.0

Собственный продукт, который я веду как открытый проект целиком: лицензия, `CONTRIBUTING`, `SECURITY`, проверки на каждый PR и релизы под две ОС.

- **Что это.** Настольное приложение, в котором документация эндпоинта и живой запрос к нему лежат на одной странице: параметры, тело и ответы описываются рядом с панелью «Try it», туда же добавляются ERD-диаграммы, WebSocket-документы и заметки. Работает офлайн, без аккаунта и сервера — данные лежат в локальном SQLite рядом с приложением, платформа целиком выгружается и переносится zip-архивом.
- **Релизный процесс.** Каждый PR проходит `cargo clippy -D warnings`, форматирование и тесты обеих частей; по тегу GitHub Actions собирает установщики под Linux и Windows и публикует релиз — v1.2.0 собран этим пайплайном без ручных шагов.
- **Инженерные решения.** Доступ к данным спрятан за трейтами репозиториев, поэтому тесты сценариев идут на фейковых реализациях без мок-фреймворков. HTTP-слой на reqwest держит прокси и таймауты на окружение и хранит куки сессии привязанными к выдавшему их хосту, чтобы токен не утёк на чужой адрес при переключении окружений. ERD собирается интроспекцией живой базы (PostgreSQL, MySQL, SQLite): читаются только метаданные схемы, данные таблиц не запрашиваются, реквизиты подключения не сохраняются.
